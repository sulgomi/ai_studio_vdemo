# 06 CVP·컨셉 (concept)

## 1. 역할

선택된 기회 셀을 서로 다른 컨셉 3안으로 구체화한다. 안마다 CVP(누구·니즈·제안·핵심 혜택·대안·차별점·믿을 근거), 특별한 포인트, 혜택 산정 구조(코드가 손익·복잡도를 계산할 수 있는 형태), 작동 방식, 가정, 시장성 검증 질문을 낸다.

하지 않는 일: 최종 상품명·카드 외관·홍보 문구(디자인·마케팅 몫), 수익성·규제 판단(코드 평가와 가드레일 몫), 확정 수치(혜택률은 검토 범위 안의 설계값).

## 2. 위치

S4. 다운스트림: 코드 평가(eval_concepts) → winner → validation, guardrail, design_marketing, plan_doc. 재작업으로 돌아오는 곳: validation(채택 미달), guardrail(fix), H4(사람 재작업 요청).

## 3. 입력

봉투 + payload: pick(H2에서 고른 셀), segment_pack(허용 태그, 카테고리, 제약, 세그먼트), comp_empty, comp_crowded, benchmarks(경쟁 카드 혜택률 범위), consumer, n_options, feedback(재작업 시 가드레일 수정안·채택 미달 사유·사람 의견).

## 4. 처리 흐름

| 단계 | 종류 | 내용 |
|---|---|---|
| design | LLM | 3안. 안마다 설계 레버(혜택 구조, 타깃 세분, 고객 경험, 제휴 구조)가 서로 달라야 함 |
| validate | 코드 | 스키마, 금칙어, 태그 등록 여부, 혜택률 0 초과 0.03 이하, 특별한 포인트 클리셰 검사(흔한 표현뿐이면 무효, 기존 카드 설명과 같으면 무효, 흔한 구조면 경고) |
| novelty(선택) | 코드 + 경량 LLM | 안마다 웹 검색 2회로 같은 상품이 이미 있는지 판정(same은 A~C 등급 근거 필요, 옵션 무효). 비용 모드 standard 이상에서만 |
| eval | 코드 | 오케스트레이터 5절 지표 계산, 통과 판정, 승자 |

## 5. 출력

`result.options[3]`: working_title, lever, variation, one_liner, segId, need, hook, special_point, cvp, tags, rates, capPerCat, fee, minPerf, cx, links, mechanics, evidence_ids, assumptions, hypotheses, risks, rationale.

다음이 읽는 필드: 코드 평가(segId, need, tags, rates, capPerCat, fee, minPerf, cx, links, mechanics, special_point), validation·guardrail(winner.card 전체), design_marketing(one_liner, hook, special_point, cvp, mechanics, working_title), plan_doc(전체).

## 6. 요건

| ID | 요건 | 검사 |
|---|---|---|
| CO-R1 | 정확히 3안, 레버가 서로 다름 | 코드 |
| CO-R2 | 금칙어(최고, 무조건, 100%, 최대, 확정, 무제한) 없음 | 코드 |
| CO-R3 | tags는 allowed_tags 키, 공백 태그 1개 이상 포함 | 코드 |
| CO-R4 | rates의 카테고리는 segment_pack.categories 키, 값은 0 초과 0.03 이하 | 스키마 + 코드 |
| CO-R5 | special_point 4요소 필수, 흔한 표현("다양한 혜택", "높은 할인율", "MZ 맞춤", "커피·OTT·편의점 n% 할인", "전월 실적 없이")만이면 무효 | 코드(클리셰 사전) |
| CO-R6 | cvp.reason_to_believe는 입력 근거 id 또는 "가정" | 코드 |
| CO-R7 | mechanics는 작동 조건을 숫자·조건으로(대상, 적립, 조건, 한도, 고지) 3줄 이상 | 스키마 + 심사 |
| CO-R8 | 투자 연계(links에 sec)면 mechanics에 원금 손실 고지 문장 | 코드 |
| CO-R9 | 이름·약속이 작동 방식보다 강하게 읽히지 않음(수익 암시 금지) | 가드레일이 재검사 |
| CO-R10 | 체리피킹 방어 장치(한도, 조건, 변경 주기) 최소 1개 | 지시 + 가드레일 |
| CO-R11 | hypotheses는 시장성 검증에서 페르소나에게 물을 질문 2개 이상 | 스키마 |

## 7. 검증기와 반려

COUNT_OUT_OF_RANGE(R1), BANNED_WORD(R2), ENUM_UNKNOWN(R3, R4), SPECIAL_POINT_INVALID(R5), ID_UNKNOWN(R6), MISSING_DISCLOSURE(R8), GATE_FAILED(평가 통과 0건: 미달 지표와 값을 message에).

## 8. 게이트·회수

후보 통과 게이트(01 문서 4절). 재작업 2회째부터 Opus. 재작업 입력의 feedback에 가드레일 suggestion, 채택 미달 시 최다 거절 사유(top_reject: inertia, complexity, low_value 등), 사람 의견을 넣는다.

## 9. 도구

없음(novelty는 오케스트레이터가 별도 단계로 실행).

## 10. 모델

기본 Sonnet, 재작업 2회째부터 Opus. 근거: A 실험 통과 후보 수 Sonnet 2, Opus 1, Haiku 1. Haiku는 입력 발행일을 잘못 읽고 투자 축이 약한 안을 냈다. 실행마다 편차가 커서 1회 결과로 우열을 말할 수 없다.

## 11. 평가

- 안 3개의 레버 분산, 특별한 포인트 무효율, 통과 후보 수(같은 입력 3회 평균)
- 상품개발부 블라인드 평가(새로움, 실현성, 수익성, 단순함 루브릭, A 결정 D11)
