# 14 반박 검증 (critic)

## 1. 역할

공백 후보(12) 또는 아이디어(13)를 받아 **렌즈 하나**의 관점에서 반박을 시도하고 투표한다. 후보 작성자는 자기 결과를 좋게 쓰기 쉬워서, 검증은 살리려 하지 않고 무너뜨릴 수 있는지 먼저 시도한다. 근거 없이 지지하지도, 근거 없이 반박하지도 않는다.

렌즈 4종: **existing**(이미 시판 중인가, 놓친 비슷한 카드), **evidence**(인용 근거가 주장을 뒷받침하는가, 연령·카드 종류 비약), **risk**(규제·수익 구조·악용·운영), **novelty**(아이디어의 참신함 반증, 아이디어 전용).

하지 않는 일: 새 후보·아이디어 제안, 최종 순위 결정.

## 2. 위치

12, 13 다음. 렌즈마다 병렬 호출한다. 결과는 코드가 집계한다(어느 렌즈든 폐기면 탈락, 조정 등급의 중앙값으로 순위). 발산(13)에 쓴 모델 계열과 **다른 계열**로 돌리는 것을 권한다.

## 3. 입력

봉투 + payload: lens, subject_kind(gap_candidate | idea), subjects(전체 대상, 누락 없이), evidence, competitor_cards, constraints, search_available.

## 4. 처리 흐름

| 단계 | 종류 | 내용 |
|---|---|---|
| attack | LLM + 도구 | 대상마다 렌즈별 반박을 시도한다(카드 대조, 근거 원문 확인, 규정 대조, 필요하면 웹 검색) |
| vote | LLM | confirm / weaken / refute와 등급을 낸다 |
| check | 코드 | 모든 대상 판정, 투표-등급 일관성, 인용 id 실재, 렌즈별 필수 필드 |

## 5. 출력

`result`: lens, search_available, checks(subject_id, vote, grade, findings, corrections, confidence_in_vote, lens_fields), cross_notes.
등급: 공백 후보는 강/중/약/폐기, 아이디어는 A/B/C/X. lens_fields: existing·novelty는 가장 비슷한 실제 카드와 참신성 판정, evidence는 수요 근거 종류(직접/간접/없음)와 가장 약한 연결, risk는 막힘 여부와 가드레일이 먼저 확인할 것, 수익 구조(비용을 키움/중립/줄임).

## 6. 요건

| ID | 요건 | 검사 |
|---|---|---|
| CR-R1 | 입력 subjects 전부에 판정이 있다(누락 금지) | 코드 |
| CR-R2 | refute이면 등급은 폐기/X 또는 약/C, confirm이면 폐기/X가 아님(confirm은 "주장이 반박을 견뎠다"는 뜻이라 원래 강도가 약이면 약일 수 있다) | 코드 |
| CR-R3 | findings가 인용한 근거 id는 입력 evidence 또는 subjects에 실재 | 코드 |
| CR-R4 | 아이디어 검증은 렌즈별 필수 lens_fields를 채운다(공백 후보 검증은 선택) | 코드 |
| CR-R5 | search_available=false인 existing 렌즈가 "비슷한 것을 못 찾았다"(confirm/weaken)고 판정할 때 confidence_in_vote는 high일 수 없다(DB만으로 부재를 증명할 수 없음). 기존 카드를 찾아서 refute하는 판정에는 적용하지 않는다 | 코드 |
| CR-R6 | refute는 핵심 전제가 틀렸다고 입증될 때만. 근거 없는 반박 금지 | 지시 + 심사 |
| CR-R7 | 수치를 계산해 새로 만들지 않고, 설계값(design_value)을 근거로 취급하지 않는다 | 지시 |

## 7. 검증기와 반려

COUNT_OUT_OF_RANGE(CR-R1), SCHEMA_INVALID(CR-R2, R4), ID_UNKNOWN(CR-R3), GATE_FAILED(CR-R5).

## 8. 게이트·회수

집계는 코드: 어느 렌즈든 폐기/X면 탈락, 등급 합산과 중앙값으로 순위. 2/3 렌즈가 refute면 탈락 사유로 기록한다.

## 9. 도구

existing·novelty 렌즈: web_search, web_fetch. evidence·risk 렌즈: 없음(근거 팩과 규정 사실을 직접 읽는다).

## 10. 모델

existing·risk·novelty: Opus(규정 해석과 반증 검색), evidence: Sonnet(원문 대조). 발산과 다른 계열을 권한다.

## 11. 평가

- 검증이 놓친 반증 비율(사람이 사후에 찾은 기존 카드 수)
- 렌즈 간 일치도, refute 후 사람이 뒤집은 비율
- 같은 대상 3회 판정의 등급 안정성

## 12. 출처

2026-10 GenZ 데모의 공백 후보 31개·아이디어 32개 검증(렌즈 3~4개). 근거 비약(체크카드 수치를 신용카드 수요로), 이미 시판 중인 상품 등 실제 반증이 나온 경험에서 렌즈를 정했다.

## 13. 한계

웹 검색이 막히면 existing 렌즈는 DB 대조에만 기대 낙관적이다. 법령 원문이 근거 팩에 없으면 risk 렌즈는 "확인 불가"로 남긴다. 검증자도 모델이라 같은 계열이면 같은 맹점을 공유할 수 있다.
