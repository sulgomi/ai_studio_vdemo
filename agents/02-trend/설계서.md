# 02 트렌드 (trend)

## 1. 역할

기준일 시점의 한국 카드·결제·소비 시장에서 기획에 의미 있는 시그널 4~6개를 웹 검색으로 찾고, 출처 URL·발행일·영향 강도·출처 신뢰도·기획 시사점을 붙인다. 규제·정책 변화는 따로 정리한다.

하지 않는 일: 특정 카드사의 내부 성과·비공개 수치 추정, 카드 혜택 비교(경쟁사 영역), 소비자 반응 분석(소비자 영역).

## 2. 위치

- 단독 대화 가능(①). 시장조사 총괄이 부름(②, ③).
- 근거 팩 모드(`purpose=evidence_pack`): 디자인·마케팅이 needs_research를 내면 해당 주제만 검색해 S-번호 출처 팩을 만든다(A 빈틈 3 해결).
- 다운스트림: consumer(id, title, impl), whitespace(id, title, impl, topic), design_marketing(전 필드 + sources), plan_doc(sources).

## 3. 입력

봉투 + payload: purpose, target, topics_hint, signal_count, research_topics(evidence_pack일 때), known_doc_ids(앞 턴 문서 메모리).

## 4. 처리 흐름

| 단계 | 종류 | 내용 |
|---|---|---|
| plan | LLM | 영역 밖 여부, 되물을 것, 검색어 최대 5개(연도·기관명 포함), 맥락 갱신 |
| search | 코드 | web_search(또는 kb_search). 결과에 doc_id, kind, tier, published를 코드가 붙임. 7일 캐시 |
| answer | LLM | 검색 문서만 근거로 signals, regulatory_changes, findings 작성 |
| check | 코드 | URL 대조, 발행일·stale 계산, 신뢰도 하향 표시, 출처 없는 숫자 제거 |

## 5. 출력

`result.signals[]`: id(T1..), title, topic, direction, period, strength, reliability, impl, source_ids. `result.regulatory_changes[]`. 출처 상세는 봉투 `sources`.

## 6. 요건

| ID | 요건 | 검사 |
|---|---|---|
| TR-R1 | 시그널 4~6개(evidence_pack은 주제당 1개 이상) | 코드 개수 |
| TR-R2 | 시그널마다 source_ids 1개 이상, 모두 이번 검색 결과 URL | 코드 대조 |
| TR-R3 | strength, reliability는 0~1 | 스키마 |
| TR-R4 | 발행일을 모르면 null, 지어내지 않음 | 지시 + 코드(검색 결과 날짜와 다르면 경고) |
| TR-R5 | 출처가 모두 18개월 초과인 시그널은 경고, 시사점에 "오래된 근거" 표시 | 코드 |
| TR-R6 | reliability 0.5 미만이면 "하향 수용" 표시, strength 낮춤 | 코드 |
| TR-R7 | impl은 카드 기획 시사점 한 문장 이상, 사실과 해석 구분 | 심사 |
| TR-R8 | 수치(채택률·손익) 추정 금지 | 코드 수치 대조 |

## 7. 검증기와 반려

COUNT_OUT_OF_RANGE(TR-R1), SOURCE_URL_UNKNOWN(TR-R2), SCHEMA_INVALID(TR-R3), SOURCE_STALE 경고(TR-R5), NUMBER_NOT_IN_INPUT(TR-R8).

## 8. 게이트·회수

충분성 검사(코드): 타깃 핵심 주제(scope의 키워드)를 다룬 시그널이 없으면 검색어를 바꿔 1회 재검색, 그래도 없으면 상위 모델(Opus)로 1회. 상한 3회에서 멈추고 부족한 부분을 unresolved에 적는다(A AWS 22절).

## 9. 도구

web_search(기본), kb_search(AWS 이관 후 저장 자료), 둘 다 `_common/tools.schema.json`.

## 10. 모델

기본 Sonnet, 올릴 때 Opus. 검색 문서 정리·추출 보조는 Haiku 가능. 근거: 출처 확인 시 주장 뒷받침 Sonnet 8/9, Opus 5/12, Haiku 4/6. 시그널 선택은 Opus 4.75가 가장 좋았다(A 실험).

## 11. 평가

- 시나리오: C `evals/trend_scenarios.json`, D `scenarios/trend.json`(관점 수, 약한 신호, 주제 쏠림, 근거율, 중복, 최신성, 지난 연도 검색어 경고)
- 출처 실제 열람 검사(urlcheck): 표본 10건에서 주장 뒷받침 80% 이상

## 12. 출처

A `agents/01-trend`(계약·검증기·18개월 규칙), C `agents/trend/prompts.py`(system, plan, answer), C design.md 6-5(trends, regulatory_changes). signals/regulatory_changes 통합 구조와 evidence_pack 모드는 새로 정함.

## 13. 한계

- 일반 검색 API는 발행일을 거의 주지 않아 null이 많다(C README). 수집 파이프라인의 발행일 추출이 선행돼야 한다.
- 리허설에서 2019~2022년 자료를 근거로 쓴 사고가 있었다. 18개월 규칙과 published 필수 키로 막는다.
