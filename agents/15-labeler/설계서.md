# 15 근거 라벨링 (labeler)

## 1. 역할

근거 항목(사실, 트렌드, 사례, 제약 등)에 **닫힌 어휘**의 라벨(니즈, 혜택 태그, 소비 영역, 카드 관련성)을 붙인다. 이 라벨로 코드가 "이 기회영역에 관련 있는 근거"를 결정적으로 고르므로, 정확하고 보수적이어야 한다.

하지 않는 일: 근거 평가, 해석, 새 라벨 만들기.

## 2. 위치

scout 다음. 근거 색인(evidence_index) 생성의 마지막 LLM 단계. 다운스트림: 코드의 EvidenceStore 검색 → 05, 06, 12, 13, 14의 `evidence` 입력.

## 3. 입력

봉투 + payload: items(최대 200개: id, kind, text, age_scope, topic), vocab(needs, tags, domains).

## 4. 처리 흐름

| 단계 | 종류 | 내용 |
|---|---|---|
| label | LLM | 항목마다 needs(≤3), tags(≤4), domains(≤2), relevance |
| check | 코드 | 모든 id에 라벨, 어휘 안의 값만 |

## 5. 출력

`result.labels`: id → {needs, tags, domains, relevance(direct | indirect | none)}.

## 6. 요건

| ID | 요건 | 검사 |
|---|---|---|
| LB-R1 | 입력 모든 id에 라벨이 있다 | 코드 |
| LB-R2 | needs, tags, domains는 vocab 키만 | 코드 |
| LB-R3 | text가 직접 말하는 것만 붙인다. 추측하지 않고 확신이 없으면 비운다 | 지시 + 표본 심사 |
| LB-R4 | 해석(interpretation) 필드는 보지 않는다 | 지시 |

## 7. 검증기와 반려

COUNT_OUT_OF_RANGE(LB-R1), ENUM_UNKNOWN(LB-R2).

## 8. 게이트·회수

어휘 밖 값은 코드가 버리고 건수를 기록한다.

## 9. 도구

없음.

## 10. 모델

Haiku(항목당 비용이 작고 닫힌 어휘 분류). 표본 30개를 Sonnet이 재라벨링해 일치도를 본다.

## 11. 평가

- Sonnet 재라벨 일치율, 비어 있는 라벨 비율(보수성), 같은 항목 3회 라벨 안정성
- 라벨이 검색에 준 효과: 영역별 근거 slice에서 사람이 관련 없다고 본 항목 비율

## 12. 출처

2026-10 GenZ 데모에서 근거 색인 507항목을 3명이 나눠 라벨링한 실행(어휘 밖 값 0건).

## 13. 한계

니즈 'digital', 'simple'에 붙은 항목이 적었다(보수적). 라벨이 비면 검색에서 빠진다. 태그 택소노미가 바뀌면 다시 라벨링해야 한다.
