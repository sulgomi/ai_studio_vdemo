# 05 시장기회 (whitespace)

## 1. 역할

시장조사 결과와 코드가 계산한 세그먼트×니즈 기회 점수를 보고, 컨셉 개발에 넘길 기회 셀 상위 3개를 고르고 근거를 쓴다. 점수 계산은 코드, 선택과 근거 서술은 LLM이다.

하지 않는 일: 점수를 직접 매기기, 컨셉 설계, 수치 추정.

## 2. 위치

S3. 다운스트림: 실현가능성 게이트(코드) → H2(사람 선택) → concept(고른 pick), plan_doc(opportunity).

## 3. 입력

봉투 + payload: target_segment_id, segments, need_labels, research(trend 요약, competitor, consumer, lead 종합), cells_top(코드 점수 상위 12), tensions(시장조사에서 합쳐지지 않은 충돌), excluded_cells(게이트에서 빠진 셀).

## 4. 처리 흐름

| 단계 | 종류 | 내용 |
|---|---|---|
| score | 코드 | 셀 점수 = 니즈 가중치 × 공백도(1 − 혼잡 비중) × 관련 시그널 강도 평균(신뢰도 반영). 상위 12, 셀마다 채택 천장 |
| pick | LLM | 상위 3셀 선택, 근거(evidence_ids), 엔진 순서와 다르면 이유, 셀별 위험 |
| check | 코드 | 타깃 셀 1개 이상, seg·need 정의 존재, evidence_ids 실재, 천장 ≥ 목표 여부 표시 |

## 5. 출력

`result.picks[]`: rank, seg, need, engine_rank, rationale, evidence_ids, deviates_from_engine, deviation_reason, risk, origin(score | tension), ceiling(코드).

## 6. 요건

| ID | 요건 | 검사 |
|---|---|---|
| WS-R1 | 정확히 3개(셀이 3개 미만이면 있는 만큼) | 코드 |
| WS-R2 | 요청 타깃 세그먼트 셀 1개 이상 | 코드 |
| WS-R3 | seg, need는 정의된 키 | 코드 |
| WS-R4 | evidence_ids는 실재 시그널(T*) 또는 공백 태그(tag:*) 또는 니즈(need:*) id | 코드 |
| WS-R5 | 엔진 순서와 다르면 deviation_reason 필수 | 스키마 조건 |
| WS-R6 | 근거 없는 셀을 끼워 넣지 않음(evidence_ids 2개 이상) | 코드 |
| WS-R7 | 시장조사 충돌(tensions)에서 나온 셀은 origin=tension으로 표시 | 지시 |

## 7. 검증기와 반려

COUNT_OUT_OF_RANGE(WS-R1, R6), GATE_FAILED(WS-R2), ENUM_UNKNOWN(WS-R3), ID_UNKNOWN(WS-R4), SCHEMA_INVALID(WS-R5).

## 8. 게이트·회수

실현가능성 게이트(코드): 셀의 채택 천장(어떤 혁신 방식으로도 도달 가능한 최대 채택 의향)이 목표 미만이면 제외. 채택 의향 반복 실패로 돌아오면 excluded_cells에 이전 셀을 넣어 다시 고른다.

## 9. 도구

없음.

## 10. 모델

Sonnet. 근거: A 실험 Sonnet 4.5, Opus 4.25, Haiku 3.75. Haiku는 근거 없는 셀을 끼워 넣었다.

## 11. 평가

엔진과 다른 순서를 고른 이유의 타당성은 심사로만 본다(코드 확인 불가). 상위 셀의 최종 채택 비율(A 허브 품질 지표).

## 12. 출처

A `agents/04-ws`(계약·검증기·천장), A 허브 실현가능성 게이트, D 결정 15(긴장을 후보 단서로). 점수식 표기와 origin 필드는 새로 정함.

## 13. 한계

점수식 가중치와 세그먼트 수치가 가정치다. 택소노미가 거칠면 모든 셀이 비어 보인다(A 품질 레버 2).

리허설 출력(A `live/run/out_ws.json`)의 3순위 셀은 근거 id가 1개(T3)라 WS-R6에서 반려된다. 근거 없는 셀 끼워 넣기를 막으려고 의도적으로 강화한 규칙이다.
