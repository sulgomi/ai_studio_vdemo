# 12 공백 분석 (gap_analyst)

## 1. 역할

모아 둔 근거와 경쟁 카드 DB를 보고, 정해진 **각도**(예: 결제 접점, 모임·소셜, 소비 통제·신뢰, 입문·정책, 바이럴·취향) 하나에서 "한국 신용카드 시장에서 아직 채워지지 않은 포인트" 후보를 낸다. 후보마다 경쟁 카드를 대조해 "없다"는 주장을 스스로 반증하려 시도하고, 근거의 두께와 반대 증거를 함께 쓴다.

하지 않는 일: 새 근거 조사(11의 일), 컨셉 설계(13의 일), 후보 최종 순위(코드와 14의 검증 몫).

## 2. 위치

scout와 labeler 다음. 각도마다 병렬로 호출하고 결과를 14 critic이 검증한다. 다운스트림: 05 시장기회의 `ideas`/후보 영역 입력, 13 ideator의 `gap_candidates`.

## 3. 입력

봉투 + payload: angle, target, evidence(코드가 각도에 맞춰 고른 근거 `ev:`), competitor_cards(공식 페이지 기준 요약), allowed_tags, need_labels, categories, constraints, id_prefix, n_candidates, search_available.

## 4. 처리 흐름

| 단계 | 종류 | 내용 |
|---|---|---|
| select | 코드 | 각도에 맞는 근거를 라벨로 고른다(니즈·태그·영역 겹침 점수) |
| propose | LLM | 후보 4~7개: 무엇이 비어 있는지, 어떤 GenZ 근거에 기대는지 |
| falsify | LLM + 도구 | 후보마다 경쟁 카드 DB를 한 줄씩 대조하고, 가능하면 웹 검색으로 DB 밖 카드·서비스를 확인한다 |
| check | 코드 | 근거 id·카드 이름·태그 키 실재, 후보 수, 판정 필드 |

## 5. 출력

`result`: angle, candidates(gap_candidate: 제목, 공백 유형, 미충족 서술, 근거 목록, 기존 대조와 판정(none/partial/exists), 방식 태그, 니즈·영역, 강도와 이유, 반대 증거, 위험, CVP 씨앗), rejected, notes.

## 6. 요건

| ID | 요건 | 검사 |
|---|---|---|
| GA-R1 | 후보 수는 n_candidates 범위(기본 4~7) | 코드 |
| GA-R2 | genz_basis.fact_id는 입력 evidence에 실재 | 코드 |
| GA-R3 | existing_check.db_cards_compared의 카드는 competitor_cards에 실재, 3개 이상 | 코드 |
| GA-R4 | mechanism_tags는 allowed_tags 키 | 코드 |
| GA-R5 | need_key는 need_labels 키 | 코드 |
| GA-R6 | 근거 age_scope가 20대가 아니면 strength_reason에 그 한계를 쓴다 | 지시 + 심사 |
| GA-R7 | search_available=false면 판정은 DB 대조 기준임을 note에 쓴다 | 지시 |
| GA-R8 | 체크카드·적금·시장 규모 근거를 신용카드 수요로 바꿔 읽지 않는다 | 지시 + 14 critic(evidence) |
| GA-R9 | 버린 아이디어를 rejected에 이유와 함께 남긴다 | 스키마 |

## 7. 검증기와 반려

COUNT_OUT_OF_RANGE(GA-R1, R3), ID_UNKNOWN(GA-R2, R3), ENUM_UNKNOWN(GA-R4, R5).

## 8. 게이트·회수

없음. 후보의 채택·탈락은 14 critic 3렌즈 투표와 코드 집계(어느 렌즈든 폐기면 탈락, 조정 강도 중앙값으로 등급)로 정한다.

## 9. 도구

web_search, web_fetch(DB 밖 카드·서비스 확인용, 예산 이내).

## 10. 모델

Sonnet. 각도마다 병렬 실행. 앙상블(Sonnet + 다른 계열 모델)을 켜면 같은 각도에서 후보 풀이 넓어진다.

## 11. 평가

- 후보 중 14의 투표를 통과한 비율, "none" 판정이 이후 검증에서 뒤집힌 비율(낙관 편향)
- 각도 간 후보 중복률, 근거 id 실재율

## 12. 출처

2026-10 GenZ 데모에서 각도 5개로 후보 31개를 낸 실행. 그때 "없음" 판정 다수가 DB 대조에만 기댄 것이 검증에서 약점으로 드러나 GA-R3, GA-R7을 요건으로 올렸다.

## 13. 한계

택소노미(49개 태그) 안에서만 방식을 말할 수 있어 새 구조가 기존 태그에 억지로 끼워진다. 앱 기능(결제창 안내, 예산 알림 등)은 혜택 문구에 안 나와 DB 대조로는 "없음"이 낙관적이다.
