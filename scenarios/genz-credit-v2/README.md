# genz-credit-v2 — 근거 팩 v2 기반 GenZ 시나리오

근거 팩(`../genz-evidence`)과 발굴 파이프라인(`../genz-discovery`, 에이전트 11~15)의 결과를 05 시장기회 → 06 컨셉까지 이어 붙여 만든 재생용 시나리오다. 실제 LLM 호출 없이 기록을 재생한다.

| 폴더 | H2 선택 | 결과 카드 |
|---|---|---|
| `genz-credit-v2-alt/` | 1순위(`A-genz-digital-auto_best-dining`, 기본 경로) | 구독노트 (구독 장부 알아서 카드) |
| `genz-credit-v2/` | 3순위(`IDEA-GRI1`, 졸업·실적 재해석 아이디어) | 꾸준 (실적 졸업 카드) |

폴더 이름이 `-alt`인 쪽이 UI의 기본 경로(1순위)다. 만든 순서 때문에 이름이 거꾸로 붙었다.

## 재생

```
PYTHONPATH=runtime python3 -m cardstudio run --scenario genz-credit-v2 --h2 2     # 꾸준
PYTHONPATH=runtime python3 -m cardstudio run --scenario genz-credit-v2-alt --h2 0  # 구독노트
```

## 기록 만들기

`record.py`(환경변수 `RECORD_SCENARIO`)가 파이프라인을 돌려 다음에 필요한 단계를 알려 준다. 각 단계는 `prompts/<단계>.md`를 에이전트(LLM)에 주고 `out.json`을 받아 채운다. 코드 게이트가 재작업을 요구하면 `out.json`이 `out.attemptN.json`으로 밀려나고 같은 단계가 다시 대기 상태가 된다.

```
RECORD_SCENARIO=genz-credit-v2-alt CARDSTUDIO_PY=<python> python3 scenarios/genz-credit-v2/record.py --h2 0 --run-id v2alt
```

## 결과 요약 (기록 그대로)

- 꾸준: 컨셉 재작업 2회, 가드레일 재작업 1회. 채택 의향 0.438, 정적 손익 3.11, 채택 고객 손익 1.69, 적용 복잡도 0.31.
- 구독노트: 3안 모두 통과(최고 채택 의향 0.43, 정적 손익 3.22, 채택 고객 손익 1.55). 가드레일 문구 지적 2건으로 컨셉 재작업 1회.

## 한계 (숨기지 않는다)

- 시뮬레이션은 졸업 규칙, 0.5% 바닥, 구독 장부·알림 같은 앱 기능을 모델링하지 못한다. 혜택률·한도·영역 배정만 반영한다.
- 구독노트 경로는 에이전트가 하니스 자체 점검(`harness.py eval`)을 거치며 작성했다. 꾸준 경로의 1차 시도는 3안 모두 기준 미달이었다.
- 근거 점수 "강" 등급 후보는 없다. 약점은 위험·신뢰도에 그대로 적었다.
- 05의 3순위 선택은 코드 순위(8위)를 사람이 PM 관심 방향에 맞춰 끌어올린 것이다. 이 선택의 이유는 `05-whitespace/out.json`의 `deviation_reason`에 있다.
- 포지셔닝 맵의 경쟁사 좌표와 보유 카드 라인업은 시연용 예시값이다.
- 구독노트 09의 재조사에서 숏폼 채널 반응·구독 관리 이용 정도는 끝내 근거를 찾지 못해 미확인으로 남았다.
- 투자 연계는 기본 제외이며 규칙만 06에 전달한다.

## 자사(신한카드) 기준 보정 (2026-10-25)

이 서비스를 쓰는 주체는 신한카드라서, 신한카드 카드 10종은 경쟁 카드가 아니라 자사로 다룬다.

- `scenario.json`의 `own_issuer`/`own_issuers` 가 기준이다. 코드가 카드 DB와 근거 팩에 `is_own` 을 붙인다.
- 경쟁 집계(혼잡·공백 태그 수, 최근접 경쟁 카드, 기회영역의 혼잡 점수)는 경쟁 카드 40종만 쓴다. 새로움(가장 가까운 카드와의 거리)은 자사까지 포함한다. 자사와 닮으면 잠식이기 때문이다.
- 03 경쟁사는 자사를 뺀 결과와 `comparison_with_own_card`(자사 비교)를 다시 기록했다. 이전 기록은 `_superseded/03-competitor.out.신한을-경쟁에-포함.json`.
- 06은 `competitor_refs`(경쟁)와 `own_refs`(자사)를 나눠 받는다(스키마·프롬프트·검증기 반영). 대안(`alternative`)에는 자사 카드를 써도 된다.
- 사용자 뷰: 경쟁 구도는 40종 기준, 자사 비교 칸과 "자사 라인업과의 겹침" 표(카드 DB 태그 기준)를 넣었다. 가상 좌표 포지셔닝 맵은 뺐다.

**한계**
- 05~10 기록은 신한 포함 03 으로 만든 것이다. 다시 기록하지 않고, 본문에서 신한 카드를 경쟁으로 부른 곳만 "(자사)" 표기와 최근접 카드 이름으로 고쳤다(06 `alternative` 포함). 기회영역 점수(`areas.json`)도 이전 계산을 고정해 재생한다. 새로 돌리면 순위가 달라질 수 있다.
- 겹침은 혜택 태그 유사도일 뿐 회원·발급량 기반 잠식 규모가 아니다.
