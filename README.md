# 카드 신상품 기획 AI 에이전트: MVP 최종 정리본

카드 상품기획의 전 과정(시장조사 → 시장기회 → 컨셉 → 시장성 검증 → 가드레일 → 디자인·마케팅 → 기획서)을 에이전트 10개와 코드 오케스트레이터가 나눠 맡는 서비스의 MVP 기준 정리본이다. 여러 버전(ai-studio, ai-studio-live, ai_cardproduct_rnd_studio, agent-dev, design_marketing_agent)을 종합해 한 가지 구성으로 확정했다.

## 화면 여는 법

서버가 필요 없다. 파일을 더블클릭하거나 브라우저로 연다.

```
open final-mvp/ui/index.html        # macOS
```

- `ui/index.html`: 최종 체크 런처. 사용자 뷰, 개발 뷰, 참고 화면으로 가는 링크와 최종 점검표(체크 상태는 이 브라우저에 저장, JSON으로 내보내기 가능)
- `ui/user-view.html`: 사용자 뷰. 왼쪽 대화 기록, 가운데 에이전트와 대화하는 채팅(오케스트레이션·에이전트 호출이 로그로 찍히고 사람 확인 지점이 채팅 버튼으로 나옴), 끝나면 최종 요약이 채팅에 뜬다. "최종 요약해서 리포트화해줘"를 보내거나 "리포트로 보기"를 누르면 오른쪽에 HTML 리포트(에이전트별 섹션)가 열리고 HTML로 저장·인쇄할 수 있다. "개별 에이전트" 모드에서는 에이전트 10종을 하나씩 골라 샘플 대화와 리포트를 재생한다. 리허설 기록 재생이라 실제 LLM은 부르지 않는다. 입력창 위 "케이스" 선택으로 2030 투자입문자와 GenZ 특화 신용카드(`scenarios/genz-credit/` 실행 기록) 중 하나를 E2E·시장조사로 재생한다. GenZ 데이터는 `python3 samples/build_genz_ui.py`로 `ui/genz-data.js`에 만든다. GenZ 케이스의 H2(기회 셀 선택)에서는 1순위(기본 경로)와 2순위(‘GenZ × 단순함’)를 고를 수 있고, 2순위는 `scenarios/genz-credit-alt/`에서 컨셉부터 기획서까지 실제로 다시 실행한 기록(재작업 후 채택 의향 하락으로 승자가 바뀐 결과 포함)이 이어진다. 3순위와 2030 케이스의 다른 셀, H1·H3·H4·H5의 다른 선택지는 실행 기록이 없어 안내만 나온다. "개별 에이전트" 샘플 10종은 2030 케이스 기준이다. 처음 화면에는 전체 기획(E2E)과 에이전트 6종(시장조사(트렌드·경쟁사·소비자)·시장기회·컨셉·시장성 검증·디자인·마케팅·기획서) 카드가 역할 설명과 함께 뜨고, 고른 카드로 대화가 시작된다. 실행 중에는 오른쪽에 오케스트레이터와 에이전트가 서로 호출하는 연결도가 실시간으로 그려지고, 끝나면 자동으로 "기획보고서"(HTML) 탭으로 바뀐다. 기획보고서는 6개 에이전트 결과를 순서대로 나열하지 않고 주제별(핵심 요약·시장과 기회·상품 컨셉·시장성·브랜드·리스크·의사결정 요청·부록)로 통합하며, 대표 카드 이미지가 제목과 함께 맨 위에 놓인다. 보고서 최상단은 컨셉·주요 혜택·타깃 세그먼트·차별점 4요소를 강조하고, 02절에 경쟁사·자사 카드 라인업 포지셔닝 맵(자사 라인업과 좌표는 가상 데이터)을 둔다. 보고서 본문은 말줄임 없이 완결된 문장으로 쓰고 표·막대 그래프·누적 막대·KPI 타일 중심의 개조식으로 구성하고, GenZ 카드 시안(NOON·CLEAR·NIGHT)은 Opus 5.5가 만든 실물형 앞·뒷면 SVG(`ui/assets/genz_design_*.svg`)를 쓴다. 시작 카드는 가드레일을 제외한 에이전트로 구성
- `ui/dev-view.html`: 개발 단계에서 보는 화면. 파이프라인과 게이트, 에이전트 레지스트리(모델·스키마·검증기), 실행 기록 재생, 핸드오프 계약 검사, 모델 실측
- `ui/reference/agent-live.html`: 실제 LLM 리허설 실행 재생 뷰어(사용자 뷰/개발자 뷰 전환). 2.2MB, 영상 포함
- `ui/reference/campaign-report.html`, `video-preview.html`: 디자인·마케팅 에이전트의 최종 화면 원형
- `ui/reference/pm-hub.html`: 기존 PM 허브(12주 계획, 의사결정, 고객 접점 원본)

화면의 수치는 모두 2026-10-16~17 리허설 실행 기록에서 왔다. 채택 의향과 손익은 PM 가정치로 만든 가상 고객 모형의 결과이며 실제 전환율이나 손익이 아니다.

## 핵심 원칙 다섯 가지

1. **LLM은 내용(JSON)만 만들고, 흐름·계산·판정은 코드가 한다.** 점수, 채택 의향, 손익, 유사도, 출처 최신성, 금칙어는 코드가 계산하거나 검사한다.
2. **JSON이 원본이고 사람이 읽는 글은 그 위의 보기다.** 기획서와 화면 문장은 JSON에 없는 수치·사실을 만들 수 없다.
3. **출처 없는 주장은 쓰지 않는다.** 모든 근거에 URL·발행일·신뢰도를 붙이고, 18개월이 지난 출처는 경고한다.
4. **사람 확인 지점은 다섯 곳으로 고정한다.** 범위 확인, 기회 셀 선택, 컨셉 확정, 가드레일 needs_human, 영상 렌더 확정.
5. **에이전트는 기능 단위로 단순하게.** 에이전트 하나가 한 가지 산출물을 책임지고, 단독으로도 대화할 수 있다.

## 실제 연결용 런타임 코드

`runtime/`에 설계서를 실제로 돌리는 Python 코드가 있다(오케스트레이터, 에이전트 호출기, 스키마 검증, LLM provider 3종, 사람 확인 지점, SSE 서버). 지금은 `replay`로 GenZ 기본 실행과 H2 대안 분기를 저장된 기록과 같은 경로로 재현하고, 실제 호출(Anthropic·Bedrock)은 초안이다. 자세한 상태와 실행법은 `runtime/README.md`.

## 사용자 뷰 개편 (2026-10-27)
- **실행 단계 이름 통일:** 1. 시장조사 총괄(1-1 트렌드 분석, 1-2 경쟁사 분석, 1-3 소비자 분석) → 2. 시장기회발굴 → 3. CVP기획 → 4. 시장성 검증 → 5. 마케팅 → 6. 상품기획서 작성. 실행 트리, 진행 막대, 말풍선, 리포트 모두 같은 이름을 쓴다. 맨 앞 단계는 "1." 로 표기했다(요청 문구는 "01."). 바꾸려면 `ui/user-view.html` 의 `STEPS`, `NODE_LABEL`.
- **출시 전 점검(가드레일) 단계 숨김:** 트리·진행 막대·말풍선·단계별 실행 목록에서 뺐고, 점검 결과를 사람이 확인해야 넘어가던 지점(H3)도 없앴다. 점검 로직과 결과 데이터는 그대로이고 리포트의 "리스크·확인 사항"에만 쉬운 말로 나온다.
- **오른쪽 패널:** 폭을 0.8배(48% → 38.4%)로 줄이고, 트리 높이를 줄이는 대신 아래 실행 상태 영역을 크게(약 3배) 키웠다. 상태 영역은 지금 단계 이름, 상태 문구, 6단계 진행 표시를 보여 준다. 트리는 실행 순서대로 흐르는 모양으로 다시 그렸다.
- **내부 용어 정리:** 화면에 나가는 모든 글은 `clean()` 을 거친다(변수명·근거 번호·PM 가정치·needs_human 등을 쉬운 말로, 소수 점수를 %·원으로). 모델 이름·내부 링크도 사용자 뷰에서 뺐다.
- **[script] 표시:** 실행 상태·대화 문구 앞에 `/*[script]*/` 주석을 붙였다(화면에는 안 보임). `ui/` 폴더에서 `[script]` 로 검색하면 직접 고칠 문구가 모두 나온다. 데이터 JS(`genz-v2-data.js`, `genz-data.js`)는 `samples/mark_script.py` 가 붙인다.
- **확인 질문 2회(GenZ 상세 분석 케이스):** 시장기회발굴 직후(A)와 시장성 검증 직후(B)에 구체적인 질문이 나온다. 제안 질문을 누르거나 입력창에 직접 쓰면 관련 단계를 다시 확인하는 모습이 실행 흐름에 보이고, 보강 자료와 함께 답한다. 답변과 자료는 Claude Opus 5.5 가 사전 작성해 `scenarios/<시나리오>/followups.json` 에 있고(체크포인트 B의 수치는 시뮬레이션 코드로 직접 계산), 질문과 답은 리포트의 "확인 질문과 보강 자료"에 담긴다. 준비된 답이 없는 글은 가장 가까운 답으로 응답하고 그렇다고 밝힌다.

## 경쟁 카드 합치기와 질문 반영(2026-10-27)
- **경쟁 카드 DB:** 50종 → 경쟁 130종 + 자사(신한카드) 33종. 삼성·우리·하나·현대 심층 조사와 신한 자사 심층 조사, 젊은층 겨냥 추가 조사를 합쳤다(`scenarios/genz-credit-v2/merge_competitors.py`). 이에 따라 시장기회발굴(05)부터 다시 기록했다.
- **세 경로:** H2에서 1·2·3순위 셀을 고르면 각각 킵라인·픽백·첫단추 기획이 재생된다. 카드 시안(3종 앞뒷면)과 기획서도 경로마다 있다. 자세한 표는 `scenarios/genz-credit-v2/README.md`.
- **확인 질문과 최종 제안 변경:** 사용자 뷰의 질문 답변이 카드 조건(연회비·월 한도·혜택률·전월실적·추가 영역)을 바꾸면 미리 계산한 시뮬레이션 표(`variants.json`)에서 수치를 찾아 최종 제안을 갱신한다. 리포트에 "★ 최종 제안(질문 반영본)"과 "기획자 의도 반영 지도"(어떤 질문이 어떤 의도로 어디에 반영됐는지)가 들어가고, 영향을 받은 섹션 머리에 배너가 붙는다.
- **자료 JS 만들기:** `python3 samples/build_comp_ref.py`, `samples/build_genz_v2_ui.py`(변형 표 `ui/genz-variants.js` 포함), `samples/mark_script.py ui/genz-data.js`.

## 사용자 뷰 2차 개편 (2026-10-27)
- 실행 트리를 세로 흐름으로 다시 그려 약 2.5배 키우고, 아래 실행 상태 영역은 그만큼 줄였다. 로그는 건수 대신 "수집 중 → 분석 중 → 보완 중 → 마쳤습니다" 순서로 보인다.
- 각 단계 요약(말풍선)과 결과를 경로(셀)마다 다르게 만들었다. 시장조사 총괄은 세 분석 요약과 시장기회발굴로 넘기는 정보를 보여 주고, CVP기획은 후보별 타깃·니즈·혜택 대상 영역·혜택 방식·조건 카드로, 시장성 검증은 가상 고객(GenZ 가정)과 상황별 채택 의향의 뜻 설명, 마케팅은 포지셔닝·인사이트·메시지·채널·단계·KPI와 장면 흐름 스토리보드를 보여 준다.
- 마케팅 뒤 최종 확인은 "이대로 확정 / 다른 CVP로 변경"이다. 변경을 고르면 후보 3안의 시뮬레이션 수치를 비교해 보여 주고, 이 데모는 선정안 기록만 있어 선정안으로 기획서를 쓴다고 안내한다.
- 확인 질문 선택지는 화면에서 숨겼다(입력창에 직접 쓴다). 리허설 때만 주소 뒤에 `?q=1` 을 붙이면 준비된 질문 목록이 보인다. 어느 경로에서 어떤 질문이 준비돼 있는지는 `scenarios/시나리오_경우의수_정리.md`(`samples/build_coverage_report.py` 로 생성).
- 3차 보정(2026-10-27): 요약은 bullet 서식으로 바꿨다(`ui_summary.json`, `ui_summary_research.json`: 서브에이전트가 사전 작성). 1-1 트렌드 분석 맨 위에 소비 트렌드 키워드 16개(`trend_reference/consumer_keywords.json`)를 묶음별로 보여 주고 규제·정책은 따로 둔다. "니즈 중요도/가중치" 표현은 화면에서 없앴다("관심도" 등으로 풀어 씀).
