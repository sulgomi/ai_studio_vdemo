## 2. 정직하게 보여 줄 것

데모 영상에서 가장 큰 위험은 과장이다. 고객이 나중에 실제 서비스에서 다른 결과를 보면 영상 전체의 신뢰가 무너진다.

| 항목 | 지킬 것 |
|---|---|
| 데모 모드 | 저장된 실행을 재생한 화면이면 "데모 모드" 배지를 계속 표시한다. 나레이션에서도 한 번 말한다 |
| 시뮬레이션 수치 | 39.6% 같은 값이 나오는 화면에는 "가상 고객 시뮬레이션(가정 기반) · 실제 전환율 아님"을 고정 표기한다 |
| 가정치 | 목표 채택률 38%, 손익 기준 등은 "가정치"로 표기한다 |
| 시간 압축 | 실제 실행은 리허설 기준 약 9.8분이다. 편집으로 줄인 구간에는 "실제 소요 약 N분" 자막을 넣는다 |
| 리허설 발화 | 리허설 일부 발화는 규칙 기반 시뮬레이션이었다(PM 문서 3절 24번). 그런 장면을 쓰면 "AI가 실시간으로 말했다"고 표현하지 않는다 |
| 실행 간 변동 | 같은 요청도 실행마다 컨셉이 달라질 수 있다. 영상에서는 말하지 않아도 되지만, 시연 질의응답 답변을 준비한다 |
| 법률 판단 | 가드레일은 사전 점검이다. "법적으로 문제없음"으로 읽히는 자막을 쓰지 않는다 |
| 마지막 장면 | "무엇이 AI이고, 무엇이 계산이며, 무엇이 가정인지" 한 장(#10)을 넣는다 |

피할 표현(PM 문서 9-6): 예측, 보장, 정확한 전환율, 법적으로 문제없음, AI가 결정, 완전 자동. 대신 쓸 표현: 가상 검증, 가정 기반, 확인 필요, 사람 승인 후 진행.

## 3. 내용 정확성

| 항목 | 확인 방법 |
|---|---|
| 화면 숫자 | 영상에 나오는 숫자는 모두 `samples/` 출력이나 리허설 기록에 있는 값인지 대조한다. 나레이션 원고에 숫자마다 출처 파일을 주석으로 단다 |
| 카드명 | 컨셉 단계 이름('같이굴려요')과 최종 이름('함께쌓기')이 장면 순서와 맞는지 |
| 에이전트 이름 | 설계서(`02_에이전트_설계서_고객검토용.md`)의 이름과 같게 쓴다 |
| 출처 날짜 | 화면에 보이는 출처가 18개월 넘은 자료면 "오래된 근거" 표시가 화면에 같이 보이는지 |
| 내부 용어 | segId, capPerCat 같은 내부 필드명이 화면에 보이지 않는지(개발 뷰 장면은 예외로 하되 나레이션으로 설명) |

## 4. 외부 공개 시 법무·브랜드 확인

외부 고객·투자자에게 보여 줄 때는 아래를 먼저 확인한다. 고객사 내부용과 외부용을 따로 만드는 것이 안전하다.

| 항목 | 위험 | 대응 |
|---|---|---|
| 실존 카드사·카드명 | 경쟁사 분석 화면에 실존 카드명(ZERO Edition3, 현대카드 M 등)과 카드사명이 나온다 | 외부용은 카드명을 가리거나 "A사 카드"로 바꾼다. 고객사 내부용은 그대로 |
| 고객사 이름 | 고객사 실명과 부서명이 화면·나레이션에 나온다 | 외부 공개 전 고객사 동의. 동의가 없으면 "국내 카드사"로 |
| 출처 기사 | 기사 제목·매체명이 화면에 나온다 | 제목 인용 수준으로 두고 본문 캡처는 피한다 |
| 생성 디자인 | 카드 시안이 실존 브랜드를 연상시키는지 | 디자인·마케팅 에이전트 규칙(실존 브랜드 연상 금지)으로 1차 걸러지지만, 외부용은 사람이 한 번 더 본다 |
| 음악·폰트 | 상업 이용 라이선스 | 라이선스가 확인된 음원과 폰트만 사용 |
| 투자 연계 표현 | '함께쌓기 카드'는 ETF 소수점 매수와 연결된다. 영상이 투자 권유로 읽힐 수 있다 | 카드가 화면에 나올 때 "원금 보장 아님, 가상 기획 사례" 자막 |

## 5. 화면 녹화

| 항목 | 기본값 |
|---|---|
| 해상도 | 1920×1080, 30fps. 릴스용 요약은 1080×1920로 별도 편집 |
| 브라우저 | Chromium, 확대 125%(글자가 작은 표가 많음), 북마크바·확장 아이콘 숨김 |
| 화면 | 알림 끄기, 다른 탭 닫기, 바탕화면 정리. 개인 이메일·계정명이 보이지 않게 |
| 커서 | 클릭 위치 하이라이트, 이동은 천천히 |
| 데이터 | 녹화 전 브라우저 저장소를 비우고 시나리오 처음부터 재생 |
| 화면 파일 | `ui/user-view.html`, `ui/dev-view.html`은 서버 없이 열리므로 오프라인에서 녹화할 수 있다 |
| 예비 | 장면별로 따로 녹화한다. 한 번에 3분 40초를 찍으면 한 군데 실수로 전체를 다시 찍게 된다 |

## 6. 나레이션과 자막

| 항목 | 기본값 |
|---|---|
| 원고 | 스토리보드 나레이션을 기준으로, 장면당 한두 문장. 1분에 약 250~300자 |
| 목소리 | 사람 녹음 우선. 합성 음성을 쓰면 영상 끝에 표기 |
| 자막 | 상시 표시(소리 없이 보는 경우가 많다). 한 줄 25자 안팎, 화면 하단 안전 영역 안 |
| 용어 | 처음 나오는 용어(가드레일, 체리피커)는 자막에 짧게 풀이 |
| 숫자 읽기 | "39.6%"는 "삼십구 점 육 퍼센트". 자막과 화면 숫자가 같아야 한다 |
| 다국어 | 투자자 대상 영어 자막이 필요한지 미리 확인 |

## 7. 시각 연출

| 항목 | 지킬 것 |
|---|---|
| 강조 | 한 장면에 강조 하나. 줌인이나 하이라이트를 동시에 여러 곳에 쓰지 않는다 |
| 대기 시간 | AI가 일하는 동안 빈 화면이 길면 지루하다. 로그가 흘러가는 화면은 2~3배속, 결과가 나오는 순간은 정상 속도 |
| 멀티 에이전트 표현 | 세 에이전트가 동시에 켜지는 순간(#03)을 분명하게. 실제 동시 실행 로그와 시간이 맞아야 한다 |
| 전환 | 장면 전환은 단순하게(컷, 짧은 페이드). 화려한 전환은 금융 고객에게 신뢰를 깎는다 |
| 색 | 오류(빨강), 사람 확인(주황), 통과(초록)를 영상 전체에서 같은 뜻으로 |
| 접근성 | 자막과 배경 대비 4.5:1 이상. 색만으로 상태를 구분하지 않고 글자를 같이 쓴다 |

PM 문서 마일스톤 기준: 1차 데모 영상 W2 말 완성, W3 제출. 2차 데모(실구동) W7.

|---|---|---|
| W1 | 시청자·길이·톤 고객 확인(Q7), 스토리보드 확정 | PM, 팀원4 |
| W2 초 | 리허설 기록으로 화면 재생 점검, 장면별 녹화 | 팀원6 |
| W2 중 | 나레이션 원고 확정, 숫자 출처 대조 | 팀원4 |
| W2 중 | 상품개발부 시나리오 검수 30분 | PM |
| W2 말 | 편집, 자막, 내부 검수 | 팀원6, PM |
| W3 | 제출, 시연·피드백 워크숍 | PM |

제출 전 검수표

- [ ] 화면의 모든 숫자가 리허설 기록·샘플 파일과 같다
- [ ] 시뮬레이션 수치 화면마다 고지 문구가 있다
- [ ] "데모 모드" 배지가 보인다
- [ ] 시간 압축 구간에 실제 소요가 표기돼 있다
- [ ] 피할 표현(예측, 보장, AI가 결정 등)이 나레이션과 자막에 없다
- [ ] 내부 필드명이 사용자 뷰 장면에 보이지 않는다
- [ ] 외부용은 실존 카드명·고객사명 처리 방침을 따랐다
- [ ] 마지막 장면에 "실제 / 계산 / 가정" 정리가 있다
- [ ] 음원·폰트 라이선스를 확인했다
- [ ] 요약본과 기술 부록이 본편과 같은 숫자를 쓴다
